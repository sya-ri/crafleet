# Crafleet 0.4.0

Crafleet now manages worlds, plugin data and binary assets alongside configuration through the new `files` feature. Saved paths under `files/` mirror `runtime/`. JARs remain managed by server and plugin commands, and normal install, pending deployment, backup and EULA workflows continue to apply.

## Upgrade existing projects

Install with `npm install --global crafleet@0.4.0`. Node.js 24, 25 and 26 remain supported. Upgrade every operator and long-running supervisor before converting a project, then stop its server:

```sh
crafleet stop
crafleet files migrate --from config --dry-run
crafleet files migrate --from config
crafleet files diff
```

Migration moves the saved tree and converts `config.files` to `files.patterns` while preserving bytes, secret references, comparison observations and pending/active installation identities. It does not change runtime, download new JARs or operate Git. On interruption, repeat the command to complete it or add `--rollback` to restore the previous layout.

Legacy configuration is deprecated in 0.4.0 and retained for unmigrated projects through 0.5.x. Removal is scheduled for 0.6.0; migration and old backup readers remain afterward. Migrated projects use `files` commands exclusively. Warnings go to stderr so JSON stdout remains machine-readable.

## Capture and review

`files list`, `track`, `untrack`, `diff`, `capture` and `resolve` cover text and binary files. Repeated `capture --include <glob>` filters managed and new files; `--initial` enables new-file discovery and `--keep-missing` preserves saved files missing from runtime. Captures require a stopped server and the lifecycle operation lock. Conflicts, unsafe links or concurrent changes abort the complete capture. Use `recover` after interruption.

Binary diffs show SHA-256 and saved/previous/runtime byte sizes, including the size delta. Same size does not imply equal content. Divergent binary edits require explicit whole-file resolution. Text keeps the existing merge, secret-reference and formatting behavior, including the 4 MiB structured-text bound and existing TOML comment limitations.

Immutable binary objects are stored separately from JSON state. Format 3 backups embed the objects required by the active installation independently of `backup.artifacts`, and verify hashes and sizes during restore. Formats 1 and 2 remain readable. Keep the local object store intact; use verified backups for moving or recovering operating data.

See the [file management guide](../files.md) for discovery patterns and recovery details. This release uses the existing signed commit, verified package, supported-platform CI and npm provenance workflow.
