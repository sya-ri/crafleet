# Crafleet 0.4.0

Adds text and binary file management for worlds, plugin data, and assets through `files/`. JARs remain managed by server/plugin commands. Install with `npm install --global crafleet@0.4.0`; Node.js 24–26 remain supported.

## Migrate existing projects

Upgrade every operator and supervisor, then stop the server:

```sh
crafleet stop
crafleet files migrate --from config --dry-run
crafleet files migrate --from config
crafleet files diff
```

Migration preserves bytes, secret references, observations, and active/pending identities while converting `config/` and `config.files`. Resume interruption with the same command or reverse with `--rollback`. Runtime and artifact resolutions remain unchanged.

Unmigrated legacy projects remain supported through 0.5.x; removal is scheduled in 0.6.0. Migration and old backup readers remain afterward. Migrated projects use `files` exclusively; warnings stay on stderr.

## Files and backups

`files` supports tracking, diff, capture, and resolution. Stopped capture uses repeatable `--include`, `--initial` for discovery, and `--keep-missing` to retain missing saved files. Conflicts/concurrent edits abort capture; interruption uses `recover`.

Binary diffs show hashes and sizes; divergent edits need whole-file resolution. Text retains merging, secret references, the 4 MiB structured limit, and existing TOML comment limitations. Binary content is not redacted.

Format 3 backups embed required active file objects independently of `backup.artifacts`, allowing recovery without the original object store. Formats 1 and 2 remain readable. See [file management](../files.md) for capture and recovery details.
