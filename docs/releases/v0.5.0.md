# Crafleet 0.5.0

Crafleet 0.5.0 makes deployment backups optional, shows command progress and completed results as work proceeds, and speeds up configuration processing.

## Optional deployment backups

Omit `backup.repository` to use `start`, `run`, `restart`, and `deploy apply` without automatic backups, including updates to existing installations. No additional flag or confirmation is required. These operations do not prepare or download restic when the repository is omitted, even if `backup.files` or `backup.databases` is declared. `doctor` reports the repository check as `skip`.

A configured repository must remain usable, and required backups must succeed before pending changes are applied. Failure before shutdown leaves the server running; backup failure after shutdown leaves it stopped without applying pending. To retain automatic update backups, keep `backup.repository` configured.

Recovery groups must either omit the repository on every member or configure the same alias on every member. Explicit snapshot operations and `backup apply` still require a repository; `backup plan` remains available without one.

## Progress and results

Human-readable commands report their current operation and elapsed time on stderr and show results as projects or items become ready. Interactive terminals use a spinner or a download bar when the total size is known. Redirected output uses plain lines with a waiting update every ten seconds. Downloads without a known total report bytes received; a finished download is distinct from a verified, saved pending installation.

`--json` disables progress and preserves the complete structured result on stdout. Use it for automation that requires a stable result format.

## Faster configuration processing

Large YAML and JSON documents use linear duplicate-key checks. Configuration operations reuse successful parsing, validation, and secret processing for matching content within the operation. File inspection and retained-object verification overlap at most four reads per operation while preserving result order. Writes and journal commits remain sequential.

Duplicate keys, invalid secret references, unsafe paths, and changed runtime content retain their validation checks. The improvements do not change declaration syntax or file formats. Developer documentation includes reproducible configuration benchmarks; the README now documents both supported agent skill installers.

## Upgrade and compatibility

Install with `npm install --global crafleet@0.5.0`. Node.js 24, 25, and 26 remain supported. No new project or backup migration is required for this release.

Existing `files/` projects and unmigrated legacy `config/` projects remain supported. Legacy configuration is retained through 0.5.x, with removal scheduled for 0.6.0; migration and old backup readers remain afterward. See the [deprecation policy](https://github.com/sya-ri/crafleet/blob/v0.5.0/DEPRECATION.md) for the existing migration procedure.

Updating the CLI does not reload a running supervisor or runner. Preserve package files used by running processes and use the normal graceful maintenance procedure to activate updated code, accounting for server downtime.
