# Crafleet 0.3.1

Crafleet 0.3.1 adds configurable discovery of new runtime configuration files and persistent shell completion setup. It also makes `config list --candidates` a focused list of files that are not yet managed.

## Discover new configuration files

Set `config.files` in a project's `crafleet.yaml` to runtime-relative glob patterns:

```yaml
config:
  files:
    - server.properties
    - plugins/MyPlugin/config.yml
    - plugins/MyPlugin/items/**/*.yml
    - "!plugins/MyPlugin/items/generated/**"
```

Patterns are evaluated in order. Prefix a pattern with `!` to exclude matches; a later positive pattern can include them again. Paths use `/`, and `**` matches nested directories. Choose specific configuration directories because plugins can also store player data and credentials in YAML files.

Omitting `config.files` retains the existing standard Paper or Velocity candidates. An explicit list replaces those defaults; `[]` disables discovery of new files. Existing managed configuration remains managed regardless of these discovery rules.

Use `crafleet config list --candidates` to review files not yet managed, then `crafleet config capture <paths...>` to capture selected files. `config capture --initial` uses the configured candidates together with managed files; optional ban lists still require `--include-bans`. Register secret references before capture. Ordinary `config diff` and capture without paths continue to operate on managed configuration.

Discovery excludes JARs, avoids symlink targets, and bounds traversal. Missing roots and paths beneath regular files produce no candidates on Linux, macOS, and Windows; permission and unsafe-link errors remain visible.

## Persistent shell completion

Run `crafleet completion install [shell]` to preview and confirm persistent setup for Bash, Zsh, Fish, or PowerShell. Existing custom profile content is preserved. `--dry-run` inspects without writing, while noninteractive or JSON installation requires explicit `--yes`.

`crafleet doctor --shell <shell>` checks persistent completion settings and can offer confirmed setup in an interactive terminal. JSON, CI, non-terminal, `--yes`, and dry-run diagnostics remain read-only. Existing `completion <shell>` generation remains available.

## Upgrade and compatibility

Install this version with `npm install --global crafleet@0.3.1`. Node.js 24, 25, and 26 remain supported. Existing project declarations remain valid without `config.files`.

Scripts that used `config list --candidates` to include managed files must use `config list` for that inventory. The public declaration key is `config.files`; there is no `config.candidates` setting or `--untracked` listing option.

Updating the CLI makes discovery and completion setup available to new commands. It does not restart Minecraft or reload an existing supervisor or runner. Preserve package files used by running processes during installation, and use the normal graceful maintenance procedure when a runtime transition is needed.

The release ships the bundled CLI and runner, generated schemas, documentation, and agent skill. Publication requires the supported Node.js, operating-system, real-server, shell-completion, and database CI matrix to pass.
