# Crafleet 0.4.1

Fixes a supervision race when a normal operation releases its lock and another owner acquires it during inspection. Previously, the new owner file could be mistaken for an interrupted operation, causing `supervise` to exit with `BUSY` (code 4) and potentially stop a healthy server during cleanup.

Election, polling, and shutdown now compare lock identities and retry normal acquisition after a handoff. Failed owner reads get one polling interval to settle; consecutive observations of different publishing locks no longer count as one abandoned lock. Malformed, unreadable, unsafe, and ended operation locks remain blocked. No operation locks are removed automatically, and restart budgets and runtime intent are unchanged.

Install with `npm install --global crafleet@0.4.1`. Existing supervisors retain loaded code: preserve their package files and perform a graceful service restart to activate the fix, accounting for Java downtime. Updating the CLI alone does not reload them.

No declaration migration is required for this fix. Unmigrated legacy `config/` projects remain supported as described in [0.4.0](v0.4.0.md).
