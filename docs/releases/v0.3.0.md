# Crafleet 0.3.0

Adds clearer terminal output, consistent JSON automation, shell completion, piped console sessions, PostgreSQL backups, and portable JAR recovery. Install with `npm install --global crafleet@0.3.0`; Node.js 24–26 remain supported.

## Interfaces

- Terminal tables wrap full values and adapt to narrow terminals; progress uses stderr.
- `--json` emits finite documents or NDJSON for streams. Failed checks and partial operations now return `ok: false` with retained results; scripts must check both `ok` and exit code.
- `--help --json` exposes command and operation metadata. `completion <shell>` supports offline Bash, Zsh, Fish, and PowerShell suggestions.
- Workspace reads show all members; interactive changes offer target selection. Scripts explicitly use `--filter`, `-r`, or `-C`. Discovery avoids unrelated directories; directly selected `stop` works with broken YAML.
- `console --json` accepts ordered requests and acknowledges Java stdin delivery, not game execution. EOF/Ctrl-C detaches without stopping, reconnecting, or resending.

## Backups

`backup.artifacts` defaults to `none`; `local` embeds active file JARs and `all` embeds every active artifact. Format 2 verifies and deduplicates hashes; `all` restores without original JARs, cache, or provider access. Format 1 remains readable, but older CLIs reject format 2.

PostgreSQL 17/18 uses matching official clients and optional separate restore credentials. Verified staging precedes OID-checked replacement; the old DB is retained, Java stays stopped, and interruption uses the existing recovery journal. Missing privileges/roles/extensions and external sessions block progress. See the [versioned PostgreSQL guide](https://github.com/sya-ri/crafleet/blob/v0.3.0/docs/postgresql-backup.md).

## Upgrade

Existing declarations remain valid; PostgreSQL and embedding are opt-in. Runtime fixes include maintenance-lock retry races and acknowledgements that wait for Java's write callback. Updating the CLI does not reload existing runners/supervisors: preserve their package files and use graceful maintenance to activate the fixes. All supervised runtime operators still need at least 0.2.0.
