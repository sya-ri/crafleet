# Crafleet 0.3.0

Crafleet 0.3.0 makes everyday terminal commands easier to read and gives scripts a consistent JSON interface. Workspace selection, four-shell completion, and piped console sessions share the same command metadata. Backups can also include PostgreSQL databases and the exact active JARs needed for recovery.

## Terminal and automation interfaces

Plugin inventories, status, update checks, validation, and backup lists use aligned tables. Long and non-English values wrap without losing information; narrow terminals use labeled items. Progress stays on stderr, and plain output remains usable with redirected streams, `NO_COLOR`, and `TERM=dumb`.

Every command accepts `--json`. Finite operations emit one object, while followed logs, foreground processes, and JSON console sessions emit NDJSON. Structured `--help --json` describes arguments, options, target selection, and input requirements. Failed checks and partial workspace operations now report `ok: false` with a nonzero exit code while preserving per-target results; scripts must check both fields rather than treating any `result` as success.

Workspace-root read commands show all declared members. Changes and single-target commands offer an interactive picker. In JSON, CI, or noninteractive use, select targets explicitly with `--filter`, `-r`, or `-C`. A directly selected project's `stop` still works when its declaration is broken. Discovery stays within the workspace's declared project patterns.

Generate Bash, Zsh, Fish, or PowerShell completion with `crafleet completion <shell>`. Completion reads local command definitions, project and plugin names, and relevant paths without accessing providers or modifying files.

`console --json` accepts one request per line, such as `{"id":"1","command":"list"}`. Responses distinguish delivery to Java from execution inside the game. Input and output are bounded and apply backpressure; EOF, Ctrl-C, or connection loss detaches without stopping Java, reconnecting to a replacement runner, or resending commands.

## Portable backups and PostgreSQL recovery

`backup.artifacts` defaults to `none`, preserving existing behavior. Choose `local` to include active `file:` JARs or `all` to include all active server and plugin JARs. Format-2 snapshots deduplicate by SHA-256 and verify embedded bytes before use. `all` can restore without original JARs, the shared artifact cache, or provider network access. Pending or different versions are never substitutes. Existing format-1 snapshots remain readable; older CLIs cannot read the new embedded-artifact format.

PostgreSQL 17 and 18 backups use official matching-major `pg_dump`, `pg_restore`, and `psql` clients. Crafleet verifies custom archives by a full read and hash, supports separate recovery credentials, and restores into a staging database before replacing the target through an OID-checked rename. Database ownership, permissions, and settings are preserved. Missing roles, extensions, privileges, or active external connections block cutover; Crafleet neither grants privileges nor forcibly disconnects clients. The old database remains under a disabled retained name, and interrupted recovery resumes through the existing journal without automatically starting Java. Major-version migration is outside this contract.

See [PostgreSQL backup and recovery](https://github.com/sya-ri/crafleet/blob/v0.3.0/docs/postgresql-backup.md) for configuration and recovery requirements.

## Runtime fixes and compatibility

Supervision retries when maintenance releases its operation lock during a bounded owner-file read. Unsafe or abandoned locks still block operation. Runner command acknowledgements wait for the Java stdin write callback so that a slow Java reader also applies backpressure.

Install the fixed version with `npm install --global crafleet@0.3.0`. Node.js 24, 25, and 26 remain supported. Existing project and workspace declarations remain valid; PostgreSQL and artifact embedding are opt-in. All runtime operators must use at least Crafleet 0.2.0 to respect persisted running/stopped intent.

Updating the installed CLI does not reload an existing supervisor or runner. Preserve the package directory used by running processes when switching versions. Use the normal graceful service path during a separately approved maintenance window to activate runtime fixes; no automatic server restart is part of installation. New CLI features that require runner behavior, including the updated command-delivery acknowledgement, are fully active after that runtime transition.

## Verification and distribution

The release includes the CLI, bundled runner, schemas, documentation, and agent skill. Verification covers the supported Node.js runtimes, real Paper and Velocity servers on Linux/Windows/macOS, Bash/Zsh/Fish/PowerShell completion, MySQL/MariaDB, and PostgreSQL 17/18. Backup tests include interruption recovery, missing or changed JARs, legacy snapshots, and restoration without the original artifacts or cache.
