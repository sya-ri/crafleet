# Crafleet 0.2.1

Crafleet 0.2.1 fixes a supervision race that could stop a healthy server when another operation released the shared workspace lock immediately after the supervisor encountered it.

## Operation contention

Supervisor election, polling and graceful shutdown now distinguish mutex acquisition contention from other blocked operations. They wait for a live owner and retry normally if the lock has already been released. A newly created lock gets one polling interval for its owner file to be published. Persistently ownerless, malformed or ended operation locks still require deliberate inspection and recovery; duplicate supervisors remain rejected.

Each retry reacquires the normal operation lock. This change does not clear locks, apply pending installations, alter runtime intent, acquire updates or force-stop Java.

## Installation and compatibility

Install the exact published version with `npm install --global crafleet@0.2.1`. Node.js 24, 25 and 26 remain supported, with no manifest or state schema migration. Supervision was introduced in 0.2.0; all runtime operators must use at least that version to respect runtime intent.

Existing supervisor processes keep their loaded code. Restart each foreground supervisor through its normal graceful service path during an approved maintenance window to activate this fix. Account for Java downtime and preserve the service's running or stopped intent.

The release is distributed as the verified CLI tarball, including the bundled runner, schemas, documentation and skills. Regression tests cover operation completion before inspection, owner publication, supervisor election, service shutdown and fail-closed guards.
