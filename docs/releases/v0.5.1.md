# Crafleet 0.5.1

Crafleet 0.5.1 adds local configuration generated from examples, automatic Paper management-server secrets, guided command help, and colored server-log output.

## Local configuration from examples

Commit shared defaults and keep each operator's configuration outside Git:

```yaml
files:
    defaults:
        plugins/MyPlugin/hosts.yml: files/plugins/MyPlugin/hosts.example.yml
```

Add `/files/plugins/MyPlugin/hosts.yml` to `.gitignore`. The first `install` creates it when missing. Later installs compare the previous example, local file, and new example: untouched values follow default updates, local edits win, and arrays are atomic. An existing local file without history is preserved on the first install, which records its comparison baseline. YAML, JSON, TOML, and properties are supported.

Declared examples are excluded from deployment and capture. Generated files and `.crafleet/file-defaults.json` use the installation recovery transaction. `install --dry-run` writes nothing. Use the existing deploy/start/restart flow to apply the pending installation. See the [managed-files guide](https://github.com/sya-ri/crafleet/blob/v0.5.1/docs/files.md#local-configuration-from-examples).

## Paper management-server secrets

Crafleet generates and privately stores a management-server credential before supported Paper startup when one is missing, or adopts an existing valid runtime value. It does not enable the management API. Capture replaces the value with the built-in secret reference; explicit secret references and existing credentials remain supported. Inspections and dry runs do not create secret files. Keep the project's private secret store with its local state.

## Help and server logs

Running `crafleet` without a command now shows successful, guided help with command groups and setup examples. Server-log colors are preserved in supported interactive output, including the console and foreground logs. Redirected output and JSON retain their automation-oriented behavior.

## Upgrade and compatibility

Install with `npm install --global crafleet@0.5.1`. Node.js 24, 25, and 26 remain supported. Upgrade every operator using a project before adding `files.defaults`; older versions cannot read the new declaration.

No project or backup migration is required for existing configurations. Legacy `config/` projects remain supported through 0.5.x, with removal scheduled for 0.6.0. Updating the CLI does not reload an existing supervisor or runner; use the normal graceful maintenance procedure to activate updated code.
