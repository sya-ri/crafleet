# Crafleet 0.2.0

Crafleet 0.2.0 adds native restart supervision that respects explicit stops, cold backups and deployments. It also includes interactive Modrinth plugin discovery and support for every Node.js 24 release.

## Install

```sh
npm install --global crafleet@0.2.0
crafleet --version
```

The published CLI supports Node.js 24, 25 and 26. Build tooling requires Node.js 24.11.1 or later. Java requirements continue to follow the selected server. Crafleet does not install Java or register operating-system services.

## Native supervision

Start a project explicitly, then run `crafleet -C /srv/server supervise` in a terminal or a foreground service. The supervisor restarts an active installation after a server-initiated normal exit or Java crash. Explicit `crafleet stop` remains stopped, including after the supervisor restarts.

Runtime intent is local state and is visible in `status`. Supervision and lifecycle operations share the same mutex, preventing an automatic restart during backups, deployment or restoration. Failed maintenance remains stopped. Automatic restart always uses active artifacts offline and cannot apply pending changes or accept fresh EULA consent.

Automatic launches wait ten seconds and are limited to five attempts in five minutes. Failed readiness or an exhausted budget requires an explicit successful start/restart. Unknown processes, interrupted operations and unsafe locks remain blocked for deliberate inspection. Supervisor shutdown gracefully stops Java while preserving intent for the next host boot.

## Plugin discovery

`crafleet plugins add` without a source opens the interactive Modrinth search and version browser. Review the selected versions before confirming. Scripts continue to use explicit artifact sources; JSON, offline and multi-project operations do not open an interactive browser.

## Upgrade notes

Plugin inspection now handles quoted multiline descriptions accepted by Paper, including existing Emotecraft releases. This compatibility adjustment only affects parsing; descriptor validation and the original JAR bytes remain intact.

Existing projects retain their behavior until a supervisor is started. Missing runtime intent never implicitly launches a stopped server. Use version 0.2.0 or later for every runtime operator on supervised projects because older clients do not update intent. No manifest schema change is required.

For a foreground systemd service, invoke `supervise` directly, retain graceful shutdown, and prevent restart retries for the CLI's usage/blocked-state exit codes. Do not unconditionally execute `start` when the service starts, since it overrides an intentional stop.
